# Genau Mockup Screen Generator

## Purpose
Genau's prototype is a set of phone-frame screens (opening prompt, in-conversation
correction, English fallback, patterns list, words list) that all share one visual
system. New screens get added over time as the product concept grows. Without a
skill, each new screen means re-deriving the color tokens, phone chrome, orb
component, and caption style from scratch, with a real risk of drift (slightly
different radius, a new ad-hoc color, inconsistent caption tone). This skill fixes
the system once and lets any new screen be generated by supplying only what's
actually new: the content and the moment type.

## When to use this
- A new screen, state, or flow step is needed for the Genau app (e.g. "mock up a
  settings screen", "show what happens when the user gets 3 corrections right in a
  row", "add an onboarding screen").
- An existing screen needs a variant (e.g. the recast moment but for a different
  grammar topic).
- Do NOT use this for the *first* screen of a brand-new product idea, or for
  changing the visual system itself (new color palette, new frame shape) — that's
  a design decision, not a reuse of this one.

## Required inputs
Before generating, gather (ask the user if not given):
1. **Moment type** — which of the five established patterns this screen is (see
   below), or "new" if it's a genuinely new interaction shape.
2. **Screen purpose** — one sentence on what the user sees and why (e.g. "the user
   just got a correction right three times in a row").
3. **Content** — the actual German text, its English gloss, and any supporting
   copy (rule explanation, list items, labels).
4. **Tab bar state** — which of Speak / Patterns / Words should be active, if any.

## The design system (do not deviate)
Reuse this CSS token set and phone chrome verbatim; only change what a specific
screen needs.

**Color tokens**
- `--blue` (#2743E8) / `--blue-wash` — primary brand, active mic, in-line
  corrections (`<mark>`)
- `--green` (#0E7C5A) / `--green-wash` — listening state, positive/up trend
- `--plum` (#6E3AD6) / `--plum-wash` — content the *tutor supplied* to the user
  (never something the user produced alone) — e.g. `<mark class="p">`, the
  "given" word label, the supplied-sentence card
- `--amber` (#8A5A12) / `--amber-wash` — grammar rule callouts / explanations
- `--ink` / `--soft` / `--faint` — text hierarchy; `--line` for dividers
- Font: Fira Sans, 300/400/500/600/700 weights only

**Phone chrome (fixed, every screen)**
- 352×740px card, 44px radius, soft elevated shadow, `.bar` header with the
  "genau" wordmark + dot and a circular settings glyph
- Floating pill tab bar pinned to the bottom (`.tabs`), 3 tabs: Speak / Patterns /
  Words, active tab gets white pill + bold ink text

**The orb** (only appears on conversational screens, not list screens)
- `.orb.idle` — grey, no pulse — waiting for the user
- `.orb` (default/blue) — agent is speaking
- `.orb.listen` — green, pulsing — microphone is live
Pick exactly one state per conversational screen; it must match the `.state`
label text (e.g. "Ready when you are" pairs with `.idle`, "Listening" pairs with
`.listen`).

## The five moment types (extend, don't replace)
1. **Opening** — idle orb, one spoken DE line + EN gloss, a de-emphasized "do
   something else" link, mic in the off state.
2. **Recast** (in-conversation correction) — default orb, agent's corrected line
   with the fixed word in `<mark>`, EN gloss, an `.rule` amber callout explaining
   *why*, a `.you` line showing what the user actually said with the wrong part
   struck through.
3. **Fallback to English** — listening orb (green), a `.supplied` plum card
   giving the user the German sentence and asking them to repeat it, a `.you`
   line showing they answered in English.
4. **Pattern/error list** — `.stage.list` layout, `.h2` headline stating the
   insight plainly (not "Your Errors" — "What keeps slipping."), rows sorted by
   frequency, each row shows the wrong form struck through above the correct form.
5. **Vocabulary list** — `.stage.list` layout, rows with a lemma + gloss and a
   3-segment strength bar (`.bars`), items the tutor supplied are labeled
   `.given` in plum, never silently folded into "known."

When a request doesn't fit one of these five, treat it as a **new moment type**:
keep the phone chrome and color tokens fixed, but design the content layout
fresh, and add it to this list once approved so future requests can reuse it.

## Output format
A single self-contained `.html` file (inline `<style>`, Google Fonts link only
external dependency) containing:
- The full design-system `<style>` block, unchanged
- One `.phone` instance for the requested screen
- A one-paragraph `.cap` caption underneath in the same voice as the existing
  captions: name the moment, then one sentence on the product reasoning behind
  it (not just a description of what's on screen)

## Constraints
- Never invent a new color outside the five tokens above.
- Never mark tutor-supplied content the same color as user-produced content —
  this distinction (plum vs. blue) is the product's core trust signal.
- German text is the visual lead (`.de`, 25–29px); English gloss is always
  smaller and `--soft` colored, never bold.
- Keep captions honest about trade-offs, the way the original five do — don't
  write marketing copy for the caption.

## Edge cases / nuances
- If the German line is long (>~40 characters), use `.de.sm` (25px) instead of
  the default 29px so it doesn't wrap awkwardly against the phone width.
- List screens (patterns, words) never show the orb — it's reserved for
  conversational moments.
- If a screen shows the user succeeding rather than being corrected, resist the
  urge to add celebratory color/confetti — the existing system communicates
  progress through restrained trend labels (`.trend.up`) and strength bars, not
  animation.
- A screen with no natural tab-bar state (e.g. a modal or settings screen) can
  omit the `.tabs` element rather than forcing a tab to be "active."
